## 1. 执行摘要

BioJING 当前是一个功能完整的单机科普站：52 篇系列博文的展示、搜索、评论、资源下载与密码保护的管理后台均已实现，技术选型（Next.js 14 + Prisma + SQLite）与内容规模匹配，代码量约 1,800 行，结构清晰。但本次实测确认它**尚不具备公网长期运行的条件**，核心结论四条：

1. **存在可直接利用的高危漏洞（P0）**：管理页面有密码保护，但全部管理 API 未做任何服务端身份校验。本次在本地空库实证：不带任何凭证调用 `GET /api/admin/posts` 返回 200，`POST /api/admin/posts` 成功创建文章（已清理）。任何人可绕过后台增删文章、上传文件、触发备份。**这是上线前必须先修的唯一阻断项。**
2. **公开版一度无法生产构建（P1，已修复）**：`npm run build` 因 `tsconfig.json` 缺 `target` 在 `prisma/seed.ts` 的 Set 展开处报 TS2802 失败；本次已补 `target: ES2017` 并复验构建与类型检查通过。说明仓库缺少 CI 门禁，同类问题会再次漏出。
3. **内容渲染与互动链路有三处功能性缺陷**：Mermaid 图表从未真正加载渲染、Markdown 经 `rehype-raw` 直出未经净化（存储型 XSS 面）、评论默认直接公开使后台审核形同虚设。
4. **增长与运维能力缺位**：全站强制动态渲染、无 sitemap/RSS/OG、无缓存与索引优化；备份只有“导出 JSON + 记录日志”，无恢复、无校验；测试仅 3 个依赖本地状态的 pytest，无 CI、无 lint、无容器化。

升级路线分五步：**v1.0.1 安全热修复 → v1.1.0 工程化与数据治理 → v1.2.0 阅读体验与性能/SEO → v1.3.0 内容增长与生信特色 → v2.0.0 平台化升级**。每版均有明确范围、验收标准与发布门禁；涉及数据库的变更一律“先备份、验恢复、再迁移”。

### 3.2 架构与技术基线

- 单体 Next.js 应用：页面、API、后台同仓同进程；Prisma 5.14 + SQLite（`prisma/schema.prisma` 共 9 个模型：User、Series、Post、Tag、PostTag、PostFile、Comment、VisitLog、SiteSetting、BackupLog 中实际 10 个）。
- 依赖基线（2026-11 时点均已落后主流大版本）：Next 14.2、React 18.3、Prisma 5.14、Tailwind 3.4。短期可维护，须在 v2.0 做框架升级评估；`next.config.js` 里 `raw-loader` 规则引用了未安装的包、`serverComponentsExternalPackages: ['sharp']` 的 sharp 也未安装，属“暂未触发的构建地雷”。
- 数据模型问题：状态字段用裸字符串（`Post.status`、`PostFile.fileType`、`BackupLog.type/status`）无枚举约束；`Post.weekNumber/seriesId/status`、`VisitLog.createdAt` 等高频查询字段无 `@@index`；`User` 模型与 `bcryptjs` 依赖全仓未被使用，认证实际为“环境变量明文口令比对”。
- 端口：dev/start 固定 30001，符合避开 3000/8000 的约定，纳入登记保留。

### P3 — 体验与增长（规划项）

- 阅读体验：无文章目录（TOC，尽管已用 `rehype-slug` 生成锚点）、无相关推荐/系列内进度、无代码复制按钮、无暗色模式；侧边栏在移动端排到正文之后，下载资源发现成本高。
- 内容运营：无 RSS、无标签/系列落地页的 SEO 文案、无阅读量以外的转化追踪（咨询 CTA 无埋点）、关于页定价与后台站点设置未打通校验。
- 生信特色未产品化：52 篇按组学分系的资产优势未转化为“学习路径/前置知识/配套数据下载包”等结构化能力，工具/数据库外链无统一管理。

## 7. 跨版本通用门禁

1. **数据库**：任何 schema/数据变更先备份（`npm run backup` 或完整备份）并确认 `backups/` 落盘与校验和，再在副本演练，最后执行；发布说明写明备份文件与回滚命令。
2. **安全**：新增 API 必须声明鉴权与入参校验；涉及上传/Markdown/认证的改动必须附未授权与恶意输入回归用例。
3. **测试**：新功能附测试方案（正常/边界/失败三类）；合并前 typecheck、lint、build、相关测试全绿；页面改动附桌面+手机双端验收记录。
4. **文档**：行为变更同步 README 与 `docs/`；端口新增须登记（10000–90000 内选未用端口，避开 3000/8000 与已登记的 30001）。
5. **回滚**：每版发布保留上一版本构建产物与库备份；无 schema 变更的版本可直接回退代码，有迁移的版本回退前先恢复库备份。
